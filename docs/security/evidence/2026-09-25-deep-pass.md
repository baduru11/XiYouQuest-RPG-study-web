## Corrections to earlier evidence

- **Posture v1 TLS-1** (diary entries of 2026-09-24): void. Node 22 with
  OpenSSL 3 refuses to offer TLS 1.0/1.1 (`ERR_SSL_NO_PROTOCOLS_AVAILABLE`), so
  the probe never reached the server. v2 offers TLS 1.1 at security level 0;
  the server answers with a protocol-version alert, and the same probe
  completes against a host that accepts TLS 1.1, so the result is now real.
- **Posture v1 ANON-3**: void. The probe sent one of the function's twelve
  arguments and received PGRST202 (no such function, 404). With all twelve, the
  anonymous call is refused with 401 and SQLSTATE 42501, which is the evidence
  the row claimed.
- **2026-09-24 lockdown record, finding C2**: overstated. The EXECUTE grant to
  `anon` on `record_practice_progress` was a defence-in-depth gap, not a write
  path: the function refuses callers that are neither `service_role` nor the
  user named in `p_user_id` (`20260822150000_record_practice_progress_atomically.sql`).
